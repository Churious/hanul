# Hanword 2024 compatibility matrix

**Status meanings**

- **구현 완료**: connected to RHWP's document model and exercised by an automated model/export/reopen test for the stated scope.
- **부분 구현**: some paths work, but coverage, formats, selection shapes, UI integration, or platform validation is incomplete.
- **미구현**: no working Hanul command exists today.
- **검증 불가**: neither direct UI evidence nor a reliable primary source was available in this task.

The matrix records verified scope, not a claim of full Hanword compatibility. GUI/REA binary inspection is not a substitute for RHWP's file-format fidelity checks.

**Validation for this change (2026-10-14):** Windows and Ubuntu 26.04 WSL2 `npm run tauri -- build --no-bundle` both passed. Windows Tauri GUI was used with a new scratch HWP in `%LOCALAPPDATA%\Temp`; search/replace and a rectangle's insert, move/resize, Undo/Redo, save and reopen were observed. The WSLg release app opened normally despite Mesa/Zink EGL warnings; new-document rendering and rectangle insertion/selection were observed. Linux GUI resize, file save/reopen and desktop IME were not verified in WSLg. Linux X11 and Wayland desktops outside WSLg were not tested. Windows and Linux frontend tests each passed 42/42 and `npm run build` passed.

Every save path keeps the original HWP or HWPX source format and checks RHWP's content-loss report. A zero-count report means the library reported no known export loss; it is not proof that all Hancom features are fully preserved.

Hancom binary observations do not establish that Hanul can read or write a feature. Format support remains tied to RHWP behavior and Hanul round-trip tests.
