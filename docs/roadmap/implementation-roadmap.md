# Hanul 구현 로드맵

이 계획은 [기능 인벤토리](hanword-2024-feature-inventory.md)의 ID와 [격차 분석](feature-gap-analysis.md)의 상태를 연결한다. 우선순위는 기능 개수가 아니라 일상 문서 작업의 완결성, 저장 신뢰성, GUI 입력, 성능, Windows/Linux 동등성으로 정한다.

## 우선순위 기준

- **P0 — 핵심 워드프로세서**: 문서를 만들고 열어 편집하고, 표/그림/페이지를 다루며, 저장 후 다시 사용할 수 있어야 한다.
- **P1 — 실사용 완성도**: 과제·보고서·공문서 작업을 효율적으로 하고 복합 문서를 정리하는 데 중요한 기능.
- **P2 — 후순위**: 전문 작성·자동화·고급 검토 기능. 핵심 저장 안정성과 입력 품질을 해치지 않는 기반이 마련된 후 검토.
- **OUT_OF_SCOPE — 제품 범위에서 제외**: 외부 서비스 의존, Hancom 고유 생태계 또는 실행 보안·플랫폼 부담이 제품 목적과 맞지 않는 기능.

난이도 추정은 1개 구현자가 코드를 만들고 테스트·호환성 검증까지 하는 크기다. 문서 형식 세부 동작이 불명확하므로 추정은 오차가 큰 개발 규모 표식이며 일정 약속이 아니다.

- **S**: 국소 명령/UI와 단위 테스트
- **M**: 문서 모델과 UI를 함께 수정하고 회귀 테스트
- **L**: 파싱·조판·저장 또는 다중 플랫폼 GUI 검증이 필요한 기능
- **XL**: 포맷 구조 분석, 대량 fixture, 광범위한 한글 2024 호환성 검증이 필요한 기능

### 마일스톤별 우선순위/규모 표기

M0은 제품 작업에 앞서 편집 가능 여부뿐 아니라 저장 후 보존 여부를 판단할 신뢰 기반이다. M1에서 실제 입력을 검증하지 않고 포맷 호환성 기능을 늘리지 않는다. M2–M5에서 서식·표·페이지·개체를 문서 모델, 조판, UI, Undo/Redo, 저장/재열기 전체에 연결한다. M6은 같은 조판 결과의 화면/PDF/인쇄 차이를 측정한다. M7 이후는 안정된 핵심을 확장한다.

## 제외 기능과 이유

- **한컴 클라우드·외부 전송 및 계정 의존 기능**: 문서 편집기의 오프라인·개인정보 원칙에 맞지 않는다. 파일을 로컬에서 열고 저장하는 핵심을 완성한 뒤에도 별도 동의 없이 연결하지 않는다.
- **CCL/공공누리 자동 등록·점자 변환 메뉴 묶음**: 특정 공급자의 편의 흐름이다. 라이선스 문구 자체를 문서에 넣는 기능이 필요하면 일반 텍스트/메타데이터 요구를 분리해 다시 평가한다.
- **매크로/스크립트 실행과 보안 예외**: 임의 코드 실행과 문서 보안 위험이 있다. 현 제품 범위에서는 실행 기능을 제공하지 않는다.
- **배포용 문서 제한/복사 방지**: 상호운용성이 낮은 전용 제한과 DRM은 오픈 문서 편집 목적에 맞지 않는다.
- **COM 플러그인**: Windows 전용 인터페이스라 Windows/Linux 동등성 원칙과 충돌한다. 공통 확장점이 실제로 필요하면 안전한 프로세스 격리와 플랫폼 중립 API를 별도 설계한다.
- **macOS 지원**: 현 제품의 공식 개발·검증 대상이 아니다.

DAISY와 수식·차트·메일 머지 등은 범용 워드프로세서 핵심은 아니지만 지역·접근성·업무 수요가 확인되면 P2에서 재평가할 수 있다. OUT_OF_SCOPE는 모든 상황에서의 영구 금지가 아니라 현재 제품 범위 결정이다.

## 상시 품질 기준

모든 마일스톤은 다음 축을 별도로 보고한다.

1. **문서 호환성**: Hanword→Hanul→Hanword 및 역방향 편집. 개체/필드/서식/페이지 수를 구조 비교하고 손실은 저장 전에 보고한다.
2. **GUI 동작**: 마우스와 키보드, IME, 선택/커서, 컨텍스트 메뉴, 접근성 이름을 실제 앱에서 확인한다.
3. **성능**: 35·98·500쪽에서 처음 표시, 연속 입력, 표 셀 편집, 개체 드래그를 분리 측정한다. 모델·조판·SVG·WebView를 각각 기록한다.
4. **플랫폼**: Windows, WSLg, 일반 Linux X11, 일반 Linux Wayland 결과를 별도로 남긴다. 한 환경의 성공으로 다른 환경을 추정 완료 처리하지 않는다.
5. **출력**: PDF와 프린터 출력은 쪽 크기, 페이지 수, 텍스트, 글꼴 대체, 표/그림 클리핑을 별도로 검사한다.
6. **저장 안전성**: 임시 파일, 재파싱, compatibility report, 원자적 교체, 실패 시 기존 파일 보존을 계속 검증한다.

## 다음 조사와 의사결정

- 사용 빈도 높은 한글 2024 표·그림·글상자·페이지 대화상자의 직접 동작 확인을 완료한 후 대응 UI를 정한다.
- 실제 테스트 문서 corpus를 만들 때는 공개 예제나 직접 생성한 비공개 데이터 없는 fixture를 사용하고, 독점 리소스/상업 글꼴은 넣지 않는다.
- RHWP 호환 세션과 Hanul 독립 엔진의 처리 범위는 사용자 설명, 내부 로그, 저장 판정에서 동일하게 유지한다.
- REA/Ghidra는 파일 구조나 런타임 동작이 공식 자료와 안전한 fixtures로 해결되지 않을 때만 좁은 분석을 수행한다.
