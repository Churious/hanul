# Hanul 제품 목표와 기능 범위

## 제품 목표

Hanul은 Windows와 Linux에서 일상적인 문서 작성, 학교 과제, 공문서, 보고서와 표 중심 문서를 만들고 편집하는 오픈소스 HWP/HWPX 워드프로세서다. 제품 성공은 메뉴 수가 아니라 다음 품질 축으로 판단한다.

1. 문서 호환성 및 데이터 손실 방지
2. 편집 GUI의 실제 사용성
3. 문서 길이에 따른 입력·조판 반응성
4. HWP/HWPX 저장·재열기와 한글 2024 교환성
5. Windows/Linux 입력·렌더링·파일 동작
6. 인쇄 및 PDF 출력 결과

현재 저장소는 Tauri 2, React/TypeScript, RHWP WASM을 사용한다. 기능별로 Hanul 독립 문서 모델과 RHWP 호환 세션을 어댑터 뒤에서 선택한다. 독립 모델은 문단 외에 표와 그림·도형·글상자 구조도 표현하지만, 모든 HWP/HWPX 문서가 그 경로로 들어가는 것은 아니다. 가져오기 판정에 걸리는 문서는 RHWP 호환 경로를 유지한다. 독립 엔진의 HWP/HWPX 직렬화도 RHWP 기능을 이용하므로 현재 상태를 완전히 독립적인 HWP 구현으로 설명하지 않는다.

## 지원 범위

- HWP 5.x 및 HWPX 열기·편집·저장: 확인된 구조에 한해 지원한다. 포맷 이름이 지원된다는 사실만으로 모든 컨트롤·필드·서식·개체 보존을 뜻하지 않는다.
- 문단과 문자 편집, 선택, Undo/Redo, 기본 서식, 페이지 설정, 쪽 나누기, 표와 개체: 모델과 UI가 있는 범위부터 점진적으로 지원한다. 각 기능의 상세 상태는 [기능 격차 분석](feature-gap-analysis.md)을 본다.
- Windows 및 Linux: 둘 다 제품 대상이다. 테스트가 확인된 WSLg 결과는 일반 X11/Wayland 데스크톱 검증을 대신하지 않는다.
- PDF 내보내기와 인쇄: UI 및 백엔드 구현은 존재한다. 내용 정확도, 인쇄 장치 차이, GUI 전체 경로의 검증 정도는 별도 품질 축으로 관리한다.
- 한글 IME: OS가 전달하는 실제 조합 이벤트를 사용한다. 키 입력을 임의 변환해 한글을 만드는 기능은 지원 방식으로 인정하지 않는다.

## 비목표

- 한컴 클라우드, 계정, 문서마당 온라인 서비스, 유료 리소스와 연동하지 않는다.
- 한글 2024의 소스, 아이콘, 폰트, 독점 리소스를 복제하지 않는다. 동작과 메뉴 흐름만 관찰하고 자체 UI로 구현한다.
- 매크로·스크립트 실행, 문서 암호/배포 보안, 변경 추적, 전자결재 등 고위험 또는 전문 협업 기능을 핵심 편집 범위의 선행 조건으로 두지 않는다.
- 검증하지 않은 HWP/HWPX 구조를 일반 텍스트로 강제 변환하거나 손실을 숨기지 않는다.
- macOS는 현재 지원·테스트 범위가 아니다.

## 상태와 근거 읽는 법

기능 상태는 다음 네 가지 축을 혼동하지 않고 기록한다.

- 기능 상태: COMPLETED, PARTIAL, NOT_IMPLEMENTED, BROKEN, UNKNOWN
- 엔진 경로: Hanul 독립 엔진 또는 RHWP 호환 엔진
- 형식 축: HWP 가져오기, HWP 내보내기/재열기, HWPX 가져오기, HWPX 내보내기/재열기
- 플랫폼 축: Windows, Linux WSLg, 일반 Linux X11, 일반 Linux Wayland

COMPLETED는 명시된 좁은 지원 범위에서 동작 경로와 자동화 테스트가 함께 확인된 경우에만 쓴다. UI만 있거나 테스트가 합성 문서에 한정되면 PARTIAL이다. 소스와 테스트에 작동 경로가 없으면 NOT_IMPLEMENTED로 둔다. 코드 흔적은 있으나 현재 동작을 확인할 증거가 없으면 UNKNOWN이다. 재현된 결함은 BROKEN으로 기록하되, 현재 조사에서는 확인된 BROKEN 기능을 발견하지 못했다. 이는 결함이 전혀 없다는 보증이 아니다.

조사 범위와 증거 등급은 [조사 기록](research-notes.md)에, Hanword 2024 메뉴별 조사 단위는 [기능 인벤토리](hanword-2024-feature-inventory.md)에 적었다. 우선순위·의존성·개발 순서는 [구현 로드맵](implementation-roadmap.md)에 있다.

## 품질 게이트

기능 수를 진척률로 환산하지 않는다. 각 마일스톤은 아래 증거를 따로 제출해야 한다.

| 품질 축 | 통과에 필요한 증거 |
| --- | --- |
| 문서 보존 | Golden fixture와 구조 비교, 저장·재열기, 손실 보고, 기존 파일 보호 |
| 편집 GUI | 실제 리본/컨텍스트 메뉴 명령, 커서·선택·Undo/Redo, GUI 또는 접근성 자동화 |
| 성능 | 35·98·500쪽에서 모델 편집·조판·SVG·WebView 표시 시간을 분리한 측정 |
| HWP/HWPX 교환성 | 양방향 열기/저장/재열기, 한글 2024가 필요한 경우 직접 확인 |
| 플랫폼 | Windows와 Linux 결과 분리. WSLg와 일반 Linux 데스크톱을 별도 기록 |
| 출력 | PDF 페이지 수와 내용·용지 확인, 실제 인쇄 경로와 출력 장치 한계 기록 |
