# Hanul 1.0 개발 마일스톤

이 문서는 1.0에 필요한 핵심 작업을 구현·검증·커밋 가능한 단위로 나눈 실행 계획이다. 한글 2024 메뉴 전체를 복제하는 일정이 아니라, 일상적인 문서 작성과 안전한 파일 교환을 성립시키는 범위를 정한다.

기능 이름과 조사 근거는 [한글 2024 기능 인벤토리](hanword-2024-feature-inventory.md), 현재 상태와 상태 분류는 [기능 격차 분석](feature-gap-analysis.md), P0/P1/P2 배정과 장기 기능 목록은 [구현 로드맵](implementation-roadmap.md), 조사 환경과 증거 제한은 [조사 기록](research-notes.md)을 기준으로 한다. 이 문서는 해당 내용을 반복하지 않고, P0 ID를 작업별 완료 조건에 연결한다.

## 1.0 제품 완료 정의

Hanul 1.0은 보통의 학교 과제·보고서·공문서 및 표 중심 문서를 Windows와 Linux에서 열고 편집해 저장하는 버전이다. 모든 HWP/HWPX 변형과 한글 2024의 모든 고급 대화상자를 지원한다는 뜻은 아니다.

1. 지원한다고 표시한 구조는 열기, 실제 모델 편집, 저장, 재열기까지 일관되게 동작한다.
2. 처리할 수 없는 문서 요소와 저장 손실 가능성은 사용자에게 명시한다. 안전한 보존이 확인되지 않은 문서는 내보내기를 차단한다.
3. 본문 입력, 선택, 기본 서식, 표, 그림/기본 도형, 페이지 설정, 찾기·바꾸기, 실행 취소/다시 실행은 실제 GUI 명령으로 쓸 수 있다.
4. 실제 OS 입력기 조합을 검증한다. 키 이름을 한글로 치환하거나 Unicode를 직접 주입한 테스트는 IME 증거로 인정하지 않는다.
5. Windows와 Linux를 별도 결과로 평가한다. WSLg 결과는 일반 Linux X11 또는 Wayland 검증을 대체하지 않는다.
6. 35·98·500쪽 성능 결과는 모델 변경, 조판, SVG 생성, WebView 반영을 나누어 기록한다. 합성 모델 속도만으로 GUI 입력 완료를 선언하지 않는다.

### 권장 실행 순서

1. V1-01 저장 호환성 기준선을 가장 먼저 완료한다. 편집 범위를 늘리기 전에 안전하게 저장할 문서와 차단할 문서를 재현 가능하게 판정해야 한다.
2. V1-02 파일 수명주기와 V1-03 편집 명령 통합은 V1-01 뒤에 진행할 수 있다. 둘을 마친 뒤 OS별 IME V1-04와 보기/좌표 V1-05를 수행한다.
3. V1-06 글자 서식을 끝내고 V1-07 문단 서식·스타일로 이어간다. V1-08 표 구조는 V1-03 이후 병행 가능하며, 표 속성 V1-09는 구조 편집이 안정된 다음 진행한다.
4. V1-10 페이지 설정은 V1-01과 좌표 검증 뒤 진행한다. V1-11 머리말/꼬리말은 페이지 모델 및 필드 보존이 준비된 후 진행한다.

## 마일스톤 공통 완료 조건

각 작업은 해당 기능에 필요한 항목만 적용하되, 해당하지 않는 항목을 성공으로 간주하지 않는다.

- **실제 편집**: 리본/대화상자/컨텍스트 메뉴에서 모델 변경을 실행하고 화면·Undo/Redo를 확인한다. 목업이나 상태 표시만 있는 버튼은 완료가 아니다.
- **플랫폼**: Windows와 Linux 빌드 및 자동 테스트를 구분한다. IME와 GUI 항목은 Microsoft IME, Linux 데스크톱 입력기를 실제 환경에서 확인하고 WSLg/X11/Wayland를 구별한다.
- **문서 호환성**: 지원 범위별 HWP/HWPX 저장·재열기, 구조 비교 및 필요한 한글 2024 열기 확인을 기록한다. 확인하지 않은 복합 구조의 지원 범위를 넓히지 않는다.
- **데이터 안전**: 미지원 요소, 필드, 이미지 리소스, 병합 셀 등이 손실될 수 있으면 원인과 해당 구조를 보여 주거나 저장을 막는다. 실패 경로에서 원본을 보호한다.
- **성능**: 35·98·500쪽에서 파일 읽기, 파싱/모델, 변경 시간, 조판, SVG, WebView 화면 반영을 각각 기록한다. 키 입력 p95 50ms 목표와 드래그 60fps 목표를 실 GUI 측정과 함께 판단하며, 미달은 숨기지 않고 원인/후속 조치를 남긴다.

이 기준의 상세 근거와 현재 테스트 제한은 [기능 격차 분석](feature-gap-analysis.md), [성능 조사](../performance/editing-benchmark.md), [호환성 매트릭스](../compatibility/matrix.md)에 계속 기록한다. 이 문서에 숫자형 진행률은 두지 않는다.

## V1-01 완료 기록

**상태: COMPLETE (2026-10-15).** 구현은 [저장 호환성 기준선 기록](../compatibility/matrix.md#v1-01-save-compatibility-baseline-2026-10-15)에 자세히 남겼다.

- 저장 보고서 스키마 2가 `SUPPORTED`, `UNSUPPORTED`, `LOSSY`, `UNKNOWN`과 형식·엔진·범위·원인·영향 요소를 반환한다. `hanul-text`와 `rhwp-compat` 글상자 정책을 구분한다.
- React 사전 점검과 Tauri 임시 출력 검사/원자 교체 경계의 정책을 TypeScript 및 Rust 구조 프로파일 테스트로 맞췄다. 지원하지 않음/미확인은 알려진 손실 확인으로 우회할 수 없다.
- 기존 변환 손실은 확인 대화상자 후 저장하는 동작을 유지한다. 저장 계층도 확인 플래그를 검사한다. 실패 경로에서 기존 파일 바이트가 유지되는 테스트를 포함한다.
- 재사용 Golden은 한글 2024에서 검증된 본문+단일 사각형 글상자 HWP다. 텍스트/서식, 병합 표, 그림, 사각형·타원(단독 타원 HWP/HWPX 포함), 글상자, 혼합 HWPX, 머리말/꼬리말 텍스트 왕복, 필드 손실 보고, 쪽 나누기는 기존 자동 생성 HWP/HWPX 테스트를 재사용한다. 다중 문단 글상자, 다중 구역 및 알 수 없는 컨트롤은 저장 차단 정책으로 테스트한다. 필드 직렬화의 알려진 손실은 `LOSSY` 경고로 남는다.
- Windows: 프런트엔드 100/100, `npm run build`, Rust 16 passed / 1 ignored, `cargo fmt --check` 통과.
- Ubuntu 26.04 WSL: 프런트엔드 100/100, `npm run build`, Rust 16 passed / 1 ignored 통과. WSL 환경에 `rustfmt`가 없어 Linux `cargo fmt --check`는 검증하지 못했다.
- Linux GUI/IME와 한글 2024 직접 검증은 이 기준선 범위 밖이며, 새 HWP 구조의 한글 2024 호환성을 주장하지 않는다. WSL 결과는 일반 Linux 데스크톱 검증을 대신하지 않는다.

이후 FIL-07 및 XPL-04의 전체 상태는 PARTIAL이다. V1-01은 저장 정책과 실패 안전성의 기준선만 완료했으며, 더 넓은 포맷 상호운용성은 각 기능의 Golden 및 외부 검증에서 단계적으로 확인한다.

### V1-02a — 비동기 열기와 미저장 선택 보호

- `LatestDocumentLoad`가 열기 요청 버전을 관리한다. 더 새 요청, 문서 닫기, 컴포넌트 해제 뒤 늦게 끝난 파싱 결과는 활성 세션을 덮어쓰지 않고 폐기한다. 오래된 작업의 오류·완료 콜백은 새 요청의 상태 표시를 지우지 않는다.
- 미저장 대화상자의 저장/저장 안 함/취소 선택을 명시적 정책 함수로 통합했다. 저장은 기존 저장 파이프라인이 성공한 뒤에만 원래 열기·닫기·종료 작업을 이어가며, 취소/실패는 문서를 유지한다.
- 닫기 시 진행 중 로딩 표시를 초기화한다. 기존 현재 세션은 새 세션이 성공적으로 열린 후에만 교체된다.
- 자동 검증: Windows 프런트엔드 테스트 108/108 및 `npm run build` 통과, Rust workspace 16 passed / 1 ignored. Ubuntu 26.04 WSL2의 격리 검증 사본도 프런트엔드 108/108 및 빌드, Rust workspace 16 passed / 1 ignored. Linux Node 22.22.1은 잠금된 일부 패키지가 22.22.2를 요구한다는 engine 경고를 출력했다. Rust 코드는 변경하지 않았으며 두 플랫폼의 Rust 테스트는 회귀 확인이다.
- GUI 스모크: Windows Codex in-app browser의 Hanul 웹 UI에서 빈 문서 생성, 텍스트 입력 및 dirty 표시, 새 문서 확인창, 취소 후 텍스트/dirty 유지, 저장 안 함 후 빈 문서 시작을 확인했다. 문서 정보에는 파일명·경로·형식·크기·쪽/구역 수·엔진 버전·글꼴이 표시됐다. 저장 선택은 기존 브라우저 다운로드 fallback을 거쳐 보류된 새 문서로 진행했으나, GUI 도구에서 다운로드 이벤트를 받지 못해 산출 파일과 재열기는 확인하지 못했다. 이는 브라우저 UI 결과이며 Tauri 네이티브 대화상자/창 종료 검증이 아니다.
- 미완료: Tauri의 파일 열기·저장 대화상자와 최근 경로 재열기/끊어진 경로 제거, 네이티브 창 종료의 저장·폐기·취소, 실제 HWP/HWPX 재열기, 문서 제목/작성자 메타데이터 범위 및 저장 검증, Linux GUI. 따라서 V1-02와 FIL-01/04/09/15는 계속 PARTIAL이며 COMPLETE로 표시하지 않는다.

### V1-02b — 저장 트랜잭션 강화

**상태: PARTIAL (2026-10-15).** V1-02 완료를 뜻하지 않는다.

- `DocumentSaveLock`으로 겹친 저장을 막고, 저장 중 파일 열기·새 문서·닫기·끝내기 명령 및 네이티브 창 닫기를 차단한다. 파일 메뉴와 저장 확인창에도 진행 상태를 반영한다. 저장 대화상자 취소와 저장 예외는 기존 문서 경로/미저장 상태를 유지하며, V1-01의 호환성 검사 → 임시 파일 직렬화/검사 → 원자 교체 파이프라인을 그대로 사용한다.
- 저장 시점의 편집 revision을 기억한다. 디스크 쓰기 또는 손실 확인 대기 중 사용자가 추가 편집하면 저장 파일은 그보다 앞선 스냅샷이고 현재 문서는 계속 dirty로 남는다. 보류된 열기/닫기/끝내기는 최신 스냅샷이 깨끗하게 저장된 경우에만 계속한다.
- 자동 검증: Windows 프런트엔드 111/111 및 `npm run build`, Tauri `npm run tauri build -- --no-bundle`, Rust 16 passed / 1 ignored, `cargo fmt --check` 통과. Ubuntu 26.04 WSL의 격리된 프런트엔드 복사본도 111/111 및 빌드, Rust 16 passed / 1 ignored 통과(Node 22.22.1에서 일부 잠금 패키지의 22.22.2 요구 경고). Linux `cargo fmt --check`는 WSL에 `cargo-fmt`가 없어 실행하지 못했다.
- GUI 검증: Windows 격리 release 앱은 실행과 첫 화면을 캡처했지만 Computer Use 클릭이 앱의 `msedgewebview2.exe` “Chrome Legacy Window”로 전달됐다. 대상 창 재활성화 후 한 번 다시 관찰해도 변화가 없어 조작을 중단했다. Linux Ubuntu 26.04 WSLg에서는 임시 frontend copy로 Tauri 창을 실행하고 페이지가 보이는 첫 화면 및 네이티브 GTK 열기 대화상자를 확인했다. 다만 파일 선택 입력 뒤 포커스를 잃고 캡처가 검게 나와 선택·열기를 중단했다. 이 검은 캡처는 창 렌더링 실패의 증거가 아니다. 어느 쪽에서도 실제 디스크 저장, HWP/HWPX 재열기, 최근 경로 및 종료 경고는 GUI로 확인하지 못했다.
- 기존 자동 테스트는 HWP/HWPX 제품 세션 왕복, Rust 원자 저장 및 저장 실패 시 원본 유지, 최근 경로 저장/중복 제거/삭제 테스트를 계속 통과한다. 이 결과는 Tauri 네이티브 대화상자를 통한 실제 사용자 경로 검증을 대체하지 않는다.
- 남음: Windows Tauri에서 새 문서 저장·닫기·재열기, 기존 HWP/HWPX 수정·다른 이름 저장·재열기, 저장 취소/권한 실패, 최근 경로 재열기/끊어진 경로, 창 종료 Save/Discard/Cancel 조합. Linux WSLg에서는 창과 네이티브 열기 대화상자 표시까지만 확인했으며 파일 선택 이후 수명주기는 미검증이다. 따라서 V1-02 및 FIL-01/04/09/15는 계속 PARTIAL이다.
